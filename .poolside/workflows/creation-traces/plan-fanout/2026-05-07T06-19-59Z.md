## Repair attempts

### Repair 1 — duplicate React caused `Invalid hook call` in `<Task>`

- **Symptom:** Running `bunx smthrs graph ...` produced
  `TypeError: null is not an object (evaluating 'dispatcher.useContext')`
  inside `@smthrs/components/src/components/Task.js:201`,
  preceded by the familiar "Invalid hook call" notice.
- **Cause:** `bunx smthrs@latest` materialized a brand-new
  `node_modules` under `/private/var/folders/.../bunx-.../node_modules`,
  including its own copy of `react`. But the workflow module resolution
  hit the project-local `react` under
  `/Users/ben/code/custom-harness/node_modules/react`. Two React copies
  → hook dispatcher mismatch.
- **Fix:** Use the locally-installed CLI (`smthrs` 0.18.0
  is already a project dependency) via `./node_modules/.bin/smithers`.
  Single React copy, hooks resolve, graph renders cleanly.
- **Verified:** yes, on subsequent run.

### Observation (not a repair) — empty input shows `USER REQUEST: undefined`

Using `--input '{}'` produced prompts containing `USER REQUEST: undefined`
even though `inputSchema.prompt` has a `.default(...)`. Passing real
input (`--input '{"prompt":"..."}'`) renders correctly. This is Smithers'
render-mode default-application behavior, not a workflow bug. The
workflow will be invoked by callers with real input.

## Lessons for future skill improvement

1. Prefer `./node_modules/.bin/smithers` over `bunx smthrs`
   whenever the project has Smithers as a direct dependency. The skill
   currently instructs `bunx` which is a foot-gun for any project that
   uses React inside its workflow modules (i.e. every Smithers project).
   Recommend updating the SKILL.md CLI examples.
2. When elicitation is unavailable, the authoring loop should surface
   "explicit defaults I'm applying" in the reply rather than blocking on
   a question. That happened here; worth codifying.
3. `--input '{}'` is not a reliable render smoke test because Smithers
   does not eagerly apply Zod defaults for render-only mode. Passing a
   minimally-populated input in verification is safer.
